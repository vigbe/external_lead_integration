External Lead Integration

Website forms straight into your CRM

External Lead Integration exposes POST /api/v1/leads so landing pages, marketing forms and other systems can create crm.lead records without an Odoo user session. Each integration gets its own API key.

Features

What it does

One endpoint for every site

Send a JSON body with an X-API-Key header from forms, landing pages or backend services.

Hashed API keys

Keys are stored as a SHA-256 hash, shown once in a copyable dialog, and can be rotated or archived.

Configurable defaults

Sales team, salesperson, stage, source and contact rules come from Settings, not from the request.

Per-key overrides

A key can force its own sales team or salesperson for one site.

Deduplication

Optional: the same email returns the existing open lead instead of a duplicate.

Real HTTP semantics

Explicit status codes (201, 200, 400, 401, 422, 500), always with a JSON body.

Getting started

How it works

1
Install
Only the standard crm dependency.
2
Generate a key
Settings → External Lead API Keys → New. Copy it: it is shown only once.
3
Set the defaults
Pick the team, salesperson, stage, source, contact requirement and deduplication.
4
Send leads
POST to https://your-odoo/api/v1/leads with the key header and a JSON body.
Example
curl -X POST https://your-odoo/api/v1/leads \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: oo_xxxxxxxxxxxxxxxx' \
  -d '{"name": "Jane Doe", "email": "jane@example.com",
       "message": "I want a quote"}'

Details

Feature Detail
Responses 201 created · 200 duplicate · 400/401/422/500 errors, always JSON
Legacy keys Plaintext keys from older versions are hashed on their first request
Payload handling Unknown JSON keys are ignored safely; attribution stays server-side
Access control A dedicated External Lead Admin group manages the keys
Languages English and Spanish (es, es_CL)

Requirements

Item Value
Odoo 16.0 to 20.0 — Community or Enterprise
Dependencies base, crm
External services None
Deployment: run the endpoint behind a reverse proxy with rate limiting and bot protection (e.g. reCAPTCHA). For browser forms, enable CORS at the proxy, and treat keys embedded in public pages as public.
